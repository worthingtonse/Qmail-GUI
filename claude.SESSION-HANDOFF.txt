THE BLOCKER (server-side, NOT a client bug) — read this first next session
--------------------------------------------------------------------------------
Object Transfer mail still does NOT deliver. Root cause is SERVER-SIDE:
the META object (file_type 0x00) is unretrievable after the sender's
cmd 79 commit reports success. The BODY object (file_type 0x01, same
object_id/generation/servers/key) downloads fine via cmd 81/82; the meta
misses the object store and returns 0xCA (202 FILE_NOT_EXIST) from every
server on the cmd 74 fallback. Without the meta (which holds the CBDF:
subject, recipients, body framing) the email can't be assembled, so the
recipient shows "Failed to decrypt" / "queued for background decryption".
Reproduced BOTH directions, with and without a large attachment, so it is
not load- or direction-specific. Leading theory: file_type 0 treated as
"unset/default" on the server's store or (object_id,file_type) lookup, OR
tiny objects not durably persisted/indexed.

The client is behaving correctly (requests the right key, fails hard
rather than storing a corrupt email). Do NOT "fix" the client for this.
