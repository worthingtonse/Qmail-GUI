Spec verification — FIX-09 (Add Contact schema fix)
----------------------------------------------------
[x] AddContactModal renamed "Email Address" → "QMail address or
    serial number" (line 90). Two fields only (Name/Alias +
    Address-or-SN); no third description field per spec.
[x] resolveAddressOrSn(input) helper:
    - /^\d+$/ → treated as serial number, success path returns
      both serial_number and serialNumber aliases.
    - Email-shaped input → rejected with the verbatim required
      error string ("Please enter a serial number (or a QMail
      address once the lookup service is available).").
    - Other input → same error.
[x] ContactsPane.handleAddContact:
    - Resolves the input via resolveAddressOrSn BEFORE addContact.
    - On resolve failure: returns { success:false, error } so the
      modal surfaces the inline error and stays open. No
      serial_number=0 row created.
    - On success: passes the REAL serial_number, first/last name,
      and a clean description (no address stuffed into description).
[x] CONTACT_ADDRESS_OR_SN_ERROR exported as a named constant so
    AddContactModal and the helper share a single source of truth.
[x] getContacts() falls back to String(serialNumber) for autoAddress
    when the backend hasn't yet returned an auto_address — SN-only
    contacts still surface in Compose autocomplete and search.
[x] Modal close-on-success path: handleAddContact awaits
    loadContacts() then setIsAddContactOpen(false), so the list
    refresh completes before the modal closes (no stale flash).

Spec verification — FIX-12 (Buy Locker Code onboarding hint)
------------------------------------------------------------
[x] handleBuyLockerCode opens the registration page in a new tab

[x] After click, the inline hint renders below the Buy Locker Code
