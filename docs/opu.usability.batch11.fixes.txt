      downloadMailAttachment as the third argument
      (QMailDashboard.jsx:1304). downloadMailAttachment uses it as
      the defaultFilename when the Content-Disposition header is
      absent.
  [x] Dangerous-attachment confirm modal exists with the EXACT
      spec wording: "This file is flagged as potentially
      dangerous. Save anyway?" (QMailDashboard.jsx:1434).
  [x] Modal shows the filename + (optional) warning text + Cancel /
      Save Anyway buttons. Overlay click dismisses; modal click
      stopPropagation prevents accidental dismiss.
  [x] Uses existing modal pattern (mirrors AccountPane sign-out
      confirm), NOT window.confirm.

FIX-24 (Mark Unread + Archive in ReadingPane)
  [x] Mark Unread button calls onMarkAsRead(email.id, false)
      (ReadingPane.jsx:252-261).
  [x] Archive button calls onMoveEmail(email.id, "archive")
      (ReadingPane.jsx:263-275).
  [x] Archive is hidden in archive + trash folders and on already-
      trashed messages. Matches the reviewer-focus note in the GPT
      summary.
  [x] Both buttons are gated on their respective handler props, so
      they don't appear if the parent doesn't wire them.
  [x] Buttons NOT rendered for drafts — drafts use a separate
      header branch (ReadingPane.jsx:167-200) that has its own
      action set.

FIX-27 (Disable compose buttons through post-success window)
  [x] sendControlsLocked single guard at ComposeModal.jsx:867:
        const sendControlsLocked =
          isSending || sendingStatus === "completed";
  [x] Applied to Send button (line 1295) and Save Draft button
      (line 1336).
  [x] In the success branch, sendingStatus="completed" before
      isSending flips to false. Both flags then reset together
      inside the 1500ms setTimeout. So:
        - During send:           isSending=true,  status="sending"
        - During success window: isSending=false, status="completed"
        - After timeout:         isSending=false, status=null
      Both intervals satisfy sendControlsLocked === true. Buttons
      stay disabled through the whole window.
  [x] Failure branch: status="failed" + isSending=false => buttons
      re-enable so the user can retry or save. Correct.

  [x] Edit button is gated on userAccount truthy (line 370) — no

  [x] No "John Doe" / johndoe / john.doe placeholder strings

Out-of-Scope Observations
-------------------------
Recorded in docs\cla.bugs.txt:

  BUG-39 (LOW, UX polish) — Mark Unread button is unconditional;
    clicking it on an already-unread message is a no-op but a
    misleading affordance. Becomes more visible once FIX-34
    unifies the notification system (a "Marked as unread" toast

    dedicated Archive button (FIX-24) and "Archive" in the
    Move-to... dropdown are visible. Two paths for the same action.
    Suggested fix: filter "archive" out of moveOptions when the
    dedicated button is rendered.
