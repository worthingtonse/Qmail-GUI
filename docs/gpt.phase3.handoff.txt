Recent Implementation Caveats To Preserve
-----------------------------------------
- NotificationProvider now supports options objects and clickable toasts.
  Dashboard new-mail toasts preserve targetPendingGuid/targetEmailId.
- ContactsPane delete undo uses a clickable notification. Notification click
  calls restoreDeletedContact() and then removes the notification.
- ContactsPane undo currently rebuilds the contact from UI fields
  (serial/name/description). If future contact fields become important,
  carry them through the contact transform before extending undo.
- Batch 13 DRD "Add to My Contacts" marks saved rows only in component
  memory. It does not currently dedupe against already-saved local contacts
  after a reload. That is acceptable for FIX-29 but could be polished later.
- Pending-mail rows now use manual decrypt semantics. Selecting a pending
  row must not call handleDownloadMail(); only the ReadingPane Download
  Message button should decrypt.
- Search cap notice intentionally checks returned length === 50 because the
  backend does not expose paginated search/total for all matches yet.
- AccountPane Server Details now shows all returned servers; the Navigation
  RAIDA dot grid remains the primary health surface.
- QMailDashboard has several eslint-disable comments for one-time bootstrap
  effects. Avoid broad hook refactors unless the ticket requires it.
- ComposeModal is the most fragile file. Before changing it, inspect:
  attachments, touchedFields, composeContext modes, sendControlsLocked,
  send polling timeout/retry, and the network preflight override.
