FIX-39 (Compose autosave: debounced save every ~5s while typing)

      held in autosaveTimerRef (line 169).
  [x] scheduleAutosave (line 188-196) is the only public entry. It
      cancels any pending timer first, then early-returns if the
      modal is closed, currently sending, or already in the
      success-flash state (sendingStatus === "completed").
  [x] Edit paths that trigger scheduleAutosave():
        - handleRecipientChange (line 751) → To/Cc/Bcc
        - handleContactSelect (line 773) → autocomplete insertion
        - subsubject onChange (line 1236)
        - subject onChange (line 1267)
        - body onChange (line 1281)

  [x] Timer fires latestSaveDraftRef.current?.({ autosave: true })

Out-of-Scope Observations
-------------------------
Recorded in docs\cla.bugs.txt:

  BUG-49 (LOW, mount-time hygiene) — The FIX-40 persistence effect
    at ComposeModal.jsx:405-414 fires on the FIRST mount of every
    modal-open lifecycle and writes whatever readStoredShowAdvanced
    returned back into localStorage. The value being written equals
    the value just read, so this is a no-op write. It is harmless
    (the localStorage layer is synchronous and fast), but if a
    future change adds side effects to this effect (e.g. analytics
    for "advanced opened/closed"), the no-op write will fire one
    spurious "opened to last-known state" event per session.
    Suggested fix: track an initialMount ref and skip the first
    write, OR move the write into the toggle button's onClick
    instead of useEffect. Either is fine; decision-only.
