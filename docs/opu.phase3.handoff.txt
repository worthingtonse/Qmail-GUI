                 Suggested fix: silent opt-in arg on loadEmails.

                 conventions discourage backwards-compat shims.

  BUG-43  LOW   markSendFailed routes the client-side
                 "Please provide at least one valid recipient
                 address." throw through onSendFailure → dashboard

                 validation error while the modal is still open.
                 Edge case (user typed only commas / whitespace).
                 Suggested fix: move parseEmailList result check
                 into the pre-isSending validation block at the
                 top of handleSend.

  BUG-44  LOW   DRD "Add to My Contacts" saved-state is

  BUG-46  LOW   Search "Showing top 50 results" notice

  BUG-47  LOW   ContactsPane undo-notification onClick closure

Reviewer-Perspective Gotchas For Phase 3
----------------------------------------
Things I noticed across the five-batch review that aren't in
GPT's handoff and would bite the next reviewer/implementer:

1. ComposeModal.jsx is 1300+ lines and STILL has stale commented
   code (the old handleSend at lines 631-718). FIX-39 (autosave)
   will touch this file heavily. Resist the temptation to delete
   the commented block in the same patch — separate cleanup
   commit if at all.

2. The dashboard's showDashboardNotification() shim is the
   correct entry point for ALL toast emissions from
   QMailDashboard. Do NOT call addNotification directly from new
   handlers — you'll bypass the clickable-payload translation
   (targetPendingGuid → focusPendingMail; targetEmailId →
   focusInboxEmail). FIX-17's clickable-pending-toast contract
   is the most fragile cross-cutting concern in the app.

3. NotificationProvider's addNotification signature is
   (message, type, optionsOrDuration). The third arg accepts
   either a number (legacy duration) OR an options object with
   onClick / duration / timestamp / target*. Spread options
   FIRST in the object literal (before id/message/type) so
   callers can't override generated fields. Pattern is already
   established — follow it.

4. cancelledRef contract in ComposeModal handleSend MUST survive
   any refactor. The send-poll loop has FIVE cancellation gates
   (loop condition + after sleep + before onSend dispatch + at
   loop exit + before fallback onSend). FIX-39 (autosave) is
   parallel work but uses similar timer/cleanup logic — don't
   confuse the two refs.

5. ContactsPane has two distinct error states (`error` for
   global pane errors, `deleteContactError` for in-modal delete
   errors) and uses both `setError` and `showError(...)` from
   useNotification. The pattern is inconsistent (see BUG-48).
   Touch carefully.

6. AccountPane's loading gate (line 273: `if (loading &&
   raidaServers.length === 0) return spinner`) means the
   Profile section's "Loading..." placeholder (FIX-30) is only
   visible if RAIDA servers have ALREADY loaded but userAccount
   hasn't. Sequence-sensitive — test against actual mount
   timing if anyone files an "I never see Loading…" bug.

7. EmailListPane's search-cap notice (FIX-25) renders ONLY when
   searchQuery.trim() && searchResultCapHit && !isLoading.
   Three-way guard exists because earlier prototypes flashed the
   notice during in-flight searches. Don't simplify to a
   two-way guard.

8. The CONTACT delete payload is built BEFORE the destructive
   delete (ContactsPane.jsx:261). This is intentional defensive
   ordering — buildContactPayload calls resolveAddressOrSn which
   can fail. Don't reorder, even though it looks like
   premature work.

9. NavigationPane gets a raidaEchoSnapshot from Refresh (Batch
   12 wiring). If FIX-47 wires checkForNewMail back in or adds a
   "last checked" indicator, that timestamp should come from the
   SAME Refresh path — don't add a second network call.

10. Repo-wide `npm run lint` STILL fails on baseline debt
    (BUG-36). Use ONLY per-file lint as a Phase 3 gate. The
    baseline includes wallet/, vite.config.js, SenderAvatar.jsx,
    WalletSetupScreen.jsx, useGlassSounds.js.

Working Conventions (consolidated)
----------------------------------
- Default to no comments. Only when WHY is non-obvious.
- normalizeIdentityForUi returns BOTH camelCase AND snake_case.
- "Coming Soon" controls are visibly disabled, not silently
  no-op'd.
- Do NOT synthesize server state in the GUI.
- Per-file ESLint is the lint gate. npm run lint is broken.
- ContextRef + cancelledRef contracts must survive refactors —
  these are the highest-blast-radius patterns.

  / showInfo) for all new toasts. Use
  QMailDashboard.showDashboardNotification when the toast

  unrelated files. Use focused git diff per touched file.
