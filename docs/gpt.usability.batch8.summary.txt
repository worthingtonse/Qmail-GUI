Behavior implemented:
- Added an honest Trash-page delete flow. In Trash, the list header now shows a page-scoped action labelled for the visible message count, opens an in-app confirmation modal, permanently deletes only the currently loaded messages, refreshes Trash and counts, and reports how many messages remain.
- Added emptyTrashFolder(emailIds) as a GUI-side interim helper that loops deleteEmailPermanent over explicit visible IDs. It does not pretend to empty the whole Trash folder without CORE-G.
- Updated pending encrypted rows to show sender as the primary line, keep the timestamp visible, use an italic placeholder subject, include the arrival time in the preview, and suffix same-sender/same-window duplicate placeholders with #2, #3, etc.
- Pending rows now only appear in Inbox, not every folder, and their list action column no longer exposes normal read/delete controls against a pending network GUID.
- New pending-notification toasts now read "New mail from <sender>" for single arrivals and remain summary-style for multi-arrival batches.
- Clickable new-mail toasts now switch to Inbox and select the matching pending row. Keyboard activation with Enter/Space is supported.
- The mail-count growth fallback now only fetches the latest Inbox row when no pending notification is in flight.

Edge cases handled:
- Partial Trash page deletion reports partial failures and still refreshes the page/counts.
- Deleting the last page of Trash moves pagination back one page when needed.
- Duplicate pending-message suffixes are scoped to the same sender within a one-minute arrival window.
- Sign-out reset clears the new pending-mail ref used by the notification poller.

Out-of-scope bug file:
- Added a note to docs/gpt.bugs.txt that ContactsPane still uses window.confirm for contact deletion and should move to an app-styled modal when Contacts work is in scope.
