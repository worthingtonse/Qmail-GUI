Spec Verification Checklist
---------------------------
FIX-38 (Reset list pagination before sort reloads)
  Plan text: "Move setCurrentPage(0) before the API call in
  handleSortChange so the pagination widget doesn't briefly show a
  stale 'Page N of M.'"
  [x] QMailDashboard.handleSortChange (line 643-695) sets
      setCurrentPage(0) BEFORE bumping loadEmailsRequestRef and
      calling getMailList. Offset passed to getMailList is hard-zero,
      not derived from currentPage, so a stale page can't sneak in.
  [x] setSearchResultCapHit(false) also fires before the request,
      matching the FIX-25 contract that the cap notice only renders
      while a fresh search response is live.
  [x] requestId discipline preserved: the response handler bails out
      if a newer loadEmails/sort request has been issued.

FIX-44 (EmailListPane pagination consumes pageSize as a prop)
  Plan text: "EmailListPane pagination should consume page-size as a
  prop instead of hard-coding 50."
  [x] QMailDashboard passes pageSize={EMAILS_PER_PAGE} on the
      EmailListPane render (line 1653) and keeps EMAILS_PER_PAGE as
      the single source of truth in the dashboard (line 115).
  [x] EmailListPane accepts pageSize with a default of 50 (line 32) —
      back-compat for any future caller that forgets the prop, and
      keeps the eslint react/prop-types disable honest.
  [x] Pagination visibility gate uses pageSize (line 200):
        totalCount > pageSize
      Previously: totalCount > 50.
  [x] Page-count text uses pageSize (line 210):
        Math.ceil(totalCount / pageSize)
  [x] Next-button disabled logic uses pageSize (line 214):
        (currentPage + 1) * pageSize >= totalCount
  [x] No remaining hard-coded "50" in EmailListPane.jsx in a
      pagination context. The two `50` occurrences are the prop
      default (intentional back-compat) and the FIX-25 search cap
      copy ("Showing top 50 results...") — both unrelated.

FIX-46 (Italic "(no message body)" placeholder)
  Plan text: "Use italicised '(no message body)' placeholder for
  empty mail in the list."
  [x] QMailDashboard defines EMPTY_BODY_PREVIEW = "(no message body)"
      (line 45) as a single source of truth.
  [x] buildPreviewState() (line 52-70) is the single normalizer for
      list-row preview copy. It walks candidate preview strings
      first; falls back to a 100-char snip of the body if the body
      is non-blank; only when ALL of those are blank does it return
      { preview: "(no message body)", isEmptyBodyPreview: true }.
  [x] Both downloaded and local (drafts) rows are normalized through
      buildPreviewState — see loadEmails draft branch (line 520)
      and folder branch (line 567). Search results also use it
      (line 711-716).
  [x] EmailListItem applies the empty-body class only when
      isEmptyBodyPreview is set (line 128-131):
        <div className={`email-preview ${
          email.isEmptyBodyPreview ? "empty-body-preview" : ""
        }`}>
  [x] EmailListPane.css adds the italic styling without changing
      colour, weight, or line-height (line 485-487):
        .email-preview.empty-body-preview { font-style: italic; }
  [x] Pending rows DO NOT carry isEmptyBodyPreview — the
      formattedPendingMails builder (line 165-195) constructs the
      preview directly as "Waiting to decrypt. Arrived ...", never
      goes through buildPreviewState, and emits isPending:true.
      No italic regression on the encrypted-message placeholder.
  [x] Placeholder-subject styling (.placeholder-subject) is separate
      from this class and unchanged. FIX-46 is purely additive.

FIX-47 (pingQMail/checkForNewMail cleanup)
  Plan text: "Either delete the dead pingQMail import (clean) or
  wire checkForNewMail back in. Optionally show a 'last checked Xs
  ago' indicator near the RAIDA dots."
  [x] Resolved by deletion (the clean option). Grep across src\ for
      both pingQMail and checkForNewMail returns zero matches.
  [x] qmailApiServices.js no longer exports a pingQMail alias.
  [x] QMailDashboard.jsx no longer holds the commented
      checkForNewMail call in startup.
  [x] Decision is consistent with project conventions: "discourage
      backwards-compat shims when you can just change the code."
  [x] Optional "last checked Xs ago" indicator was NOT added. That
      decision is fine — the plan calls it Optional, and the RAIDA
      echo snapshot from the unified Refresh chain (Batch 12) is
      already wired into NavigationPane. Adding a timestamp later
      can use that snapshot without a second network call.

Reviewer BUG Coverage (BUG-39, BUG-40, BUG-41, BUG-42)
------------------------------------------------------
BUG-39 (LOW — ReadingPane Mark Unread shown on unread messages)
  [x] ReadingPane.jsx line 261:
        {onMarkAsRead && email.isRead && (...)}
      The Mark Unread button now only renders when email.isRead is
      true. Click-on-unread no longer surfaces a misleading
      affordance, and the unified notification system won't fire a
      "Marked as unread" toast on an already-unread message.

BUG-40 (LOW — duplicate Archive paths in inbox)
  [x] ReadingPane.jsx line 156-160: showArchiveButton is true on
      non-archive, non-trash, non-isTrashed messages — the same gate
      that decides whether the dedicated Archive button renders.
  [x] ReadingPane.jsx line 161-170: moveOptions filter now removes
      "archive" whenever showArchiveButton is true. The Move-to...
      dropdown no longer offers Archive in parallel with the button.
      Archive is still reachable from folders where the dedicated
      button is hidden (e.g. when the message is already in Archive
      itself, but currentFolder === "archive" is excluded by the
      first filter clause anyway — net behavior matches the bug
      report).

BUG-41 (LOW — Refresh chain double-notifies on loadEmails failure)
  [x] QMailDashboard.loadEmails (line 508-628) accepts an options
      object: { notifyOnError = true }. Default preserves all
      existing callers' behavior (toasts on failure).
  [x] The Refresh chain's "Message list" step (line 805-813) opts
      out with notifyOnError: false so a failure flows ONLY through
      the aggregate "Refresh completed with some service errors."
      warning toast.
  [x] notifyOnError is honored in both branches of loadEmails:
        - the error-return branch (line 609-611)
        - the catch branch (line 618-620)
      Both gate the showDashboardNotification call on the flag.
  [x] requestId discipline preserved in both branches — the catch
      handler still skips state updates if a newer load has been
      started.
  [x] Other refresh steps (RAIDA echo, Mail notifications, Mail
      counts) already throw via runRefreshStep without emitting
      their own toasts, so this fix actually unifies the contract.

BUG-42 (LOW — pingQMail backwards-compat alias unused)
  [x] Resolved together with FIX-47. The alias export is gone from
      qmailApiServices.js; zero callers in src\.
