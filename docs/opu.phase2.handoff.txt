Phase 2 conventions that bit me in Phase 1
------------------------------------------
- Default to no comments. Add one only when WHY is non-obvious. No
  "added for X flow" or "fixes #123" — that belongs in the PR.

- normalizeIdentityForUi returns BOTH camelCase and snake_case for
  every field. Don't refactor consumers to camelCase-only.

- The codebase has a lot of pre-existing eslint baseline noise
  (73 errors / 4 warnings as of Phase 1 closeout — see BUG-36).
  Use per-file lint to confirm parity or no new categories, NOT
  project-wide lint as a pass/fail signal.

- Pre-existing pattern in QMailDashboard: useEffect with `[]` deps
  captures the mount-time `loadMailCounts` (and friends). Don't
  "fix" the eslint-disable comments without understanding the
  intentional closure pattern — at least one batch has tried.

- React 18 batches state updates inside event handlers, so
  cross-component setState chains (e.g. sign-out cascading through
  App → QMail → QMailDashboard → AccountPane) commit in a single
  paint. Order the setState calls anyway — the spec calls for
  reset-before-route — but don't add manual delays.

- "Coming Soon" dead controls are visibly disabled, NOT silently
  no-op'd. Delete Account stays hidden entirely.

- Do NOT synthesize server state in the GUI. No fake Sent rows,
  fake identity health, or fake mark-as-read persistence.

- The worktree has many user/Opus changes and untracked docs. Do
  NOT reset, checkout, or revert unrelated files.

Phase 1 wisdom worth carrying into Phase 2
------------------------------------------
The fixes I added on top of GPT's Phase 1 implementations tend to
cluster around the same gotchas. Watch for these again in Phase 2:

  1. **Defensive value coercion in modal builders.** ComposeModal's
     reply/replyAll/forward branches crash on null body / null
     sender / null timestamp even when isDownloaded=true (FIX-04
     race). Coerce to "" before .replace() etc.

  2. **First-poll "ghost arrival" toast.** Pollers that fire a
     "New X arrived" toast on the FIRST fetch lie to the user
     about pre-existing data. Use an `isFirstPoll` flag.

  3. **Modal close-on-error.** Async confirm modals (Batch 8
     trash-page delete) need try/catch in the handler that the
     modal awaits, otherwise the modal stays open when the
     follow-up loadEmails / loadCounts throws.

  4. **document.title side effects.** QMailDashboard sets the
     window title in a useEffect; it persists across unmount.
     ServiceSelectionScreen doesn't reset it (BUG-26). FIX-34
     (unified notification system) is a good place to also
     centralize title management.

  5. **Notification object payloads matter.** Toasts now carry
     targetPendingGuid / targetEmailId for clickability (FIX-17).
     FIX-34 (notification unification) MUST preserve those
     payloads — string-only notifications break the clickable
     path.

  6. **Cancellation refs survive refactors.** ComposeModal's
     cancelledRef.current guard exists for a reason (BUG-04).
     FIX-33 refactors the send-poll loop; the cancellation
     contract must still break the loop on modal close.

  7. **Pre-existing race: handleReply/handleReplyAll/handleForward
     capture selectedEmail at click time.** If the user clicks
     Reply before the post-select getEmailById merge completes,
     the quoted body uses the 100-char preview. Already logged in
     docs\opu.bugs.txt. Flagged for Batch 8 in Phase 1; deferred
     out then. Worth re-evaluating if FIX-24 (Mark Unread + Archive
     buttons) touches the same handler surface.
