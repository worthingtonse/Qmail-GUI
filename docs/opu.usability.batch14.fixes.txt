Out-of-Scope Observations
-------------------------
Recorded in docs\cla.bugs.txt:

  BUG-47 (LOW, React warning) — Undo notification onClick closure
    references restoreDeletedContact → loadContacts → setContacts.
    If the user navigates away from ContactsPane within the 10s
    undo window and clicks the toast, setContacts fires on an
    unmounted component. React 18 silently drops the state update.
    Functionally correct (contact IS restored backend-side; next
    ContactsPane mount picks it up via loadContacts), just
    cosmetic noise. Suggested fix: have restoreDeletedContact
    skip the local loadContacts and rely on the next mount-time
    fetch, OR gate on a mountedRef.

  BUG-48 (LOW, consistency) — Delete-flow errors use local
    deleteContactError state + inline modal display, while every
    other ContactsPane error path uses the unified showError() from
    NotificationProvider. Defensible (inline-error keeps the user
    in-context during a preparation-failure), but inconsistent with
    Batch 12's FIX-34 unification pattern. Decision-only fix: either
    route through showError + close the modal, OR document the
    inline-error exception with a one-line comment.

Pre-existing concerns from Batch 13 review still applicable:
  - BUG-44 (DRD saved-state local on remount) — unchanged.
