Spec verification
-----------------
FIX-15 (Durable Sign Out)
  [x] qmail.skipAutoRestore localStorage key defined and gated through
      a dedicated module (src\qmail\skipAutoRestore.js).
  [x] App.checkIdentity short-circuits on the flag before
      getIdentity()/hasId() and stays on ServiceSelectionScreen.
  [x] Flag cleared on successful importCredentials() in
      ServiceSelectionScreen.handleImport.
  [x] Flag cleared on the explicit "use existing local identity"
      action.
  [x] onSignOut threaded through App → QMail → QMailDashboard →
      AccountPane.
  [x] Deep state reset in QMailDashboard.handleSignOut: emails,
      drafts, selectedEmail, mailCounts, pendingMails, walletBalance,
      composeContext, userAccount, plus interval/request refs bumped
      so any in-flight loadEmails / draft hydrate is dropped.
  [x] Ordering: flag set → localStorage.qmail.* cleared (skipping the
      flag itself) → dashboard state reset → App routed to
      SERVICES.NONE. React 18 batching unmounts the dashboard before
      any half-cleared paint commits.
  [x] In-app confirm modal (AccountPane), not window.confirm.
  [x] localStorage-unavailable degrade path: setSkipAutoRestore
      returns false; the dashboard still resets to a clean state.
      AccountPane shows a "may only last for this session" warning
      ahead of the confirm so the user knows what to expect.
  [x] qmail.* localStorage iteration uses a collect-then-remove
      pattern, so concurrent mutation doesn't skip keys.

FIX-15b (Re-entry)
  [x] ServiceSelectionScreen mounts and runs the local-identity
      check only when shouldSkipAutoRestore() is true.
  [x] Detection uses hasId() OR getIdentity().configured, matching
      the spec's "either signal is enough" guidance.
  [x] Button stacks ABOVE "I Have a Locker Code".
  [x] Distinct LogIn icon from lucide-react.
  [x] No mid-load flash — checkingLocalIdentity drives a separate
      loading row; the button only renders after the check resolves.
  [x] Cancellable: the useEffect cleanup flips a `cancelled` flag
      so a late-arriving Promise.all result doesn't overwrite state
      after unmount.
  [x] handleUseLocalIdentity clears the skip flag, then calls
      onSelectService('qmail', normalized), which seeds App's
      provisioningData and switches selectedService → QMAIL.
  [x] When hasId returns false (wallet wiped), button is not
      rendered — only the locker-import flow is offered.
  [x] localIdentityLoading and localIdentityError surface a Retry
      affordance if the late-stage loadConfiguredIdentity(3) fails.

Out-of-scope observations
-------------------------
- document.title stays at "QMail - inbox" after sign-out because no
  effect on ServiceSelectionScreen resets it. Cosmetic, pre-existing.
- skipAutoRestore.js silently swallows localStorage exceptions in
  every helper. Adding a one-line console.warn in the catch would
  help diagnose storage-quota / private-mode issues in the field.
- package.json's `build`/portable/win electron-builder sections were
  removed in the working tree alongside Batch 7 — appears unrelated
  to FIX-15/15b (a separate portable/multi-instance change). Worth
  confirming intent before any release build.

These observations have been appended to docs\cla.bugs.txt.
