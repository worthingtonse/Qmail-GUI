# CSS Refactor Plan (Gemini) - v2

This document tracks the algorithmic consolidation and refactor of CSS for the Phase 4 tracks (E1-E7).

## Core Strategy: Algorithmic Consolidation

Instead of a purely manual file-by-file refactor, we will use a "Signature-Based" consolidation approach to identify identical or near-identical styles across the codebase.

### Phase 1: Alphanumeric Inventory & Signature Mapping
We will generate an inventory of all selectors in the E1-E7 files, sorted alphanumerically by their "Attribute Signature".

**Signature Algorithm:**
1. **Key Extraction:** For every selector, we extract a list of `property: value` pairs.
2. **Value Normalization:**
   - Colors: Convert all to hex and map to the nearest design token (e.g., `#0f1419` -> `var(--primary-bg)`).
   - Spacing: Convert `px` to `rem` and round to the nearest 0.25rem bucket (the project scale).
   - Typography: Map `font-size` to the 6-tier `--font-size-*` scale.
3. **Canonical Signature:** Sort the normalized `property: value` strings alphabetically and join them (e.g., `background:var(--card-bg);padding:var(--space-md);`).
4. **Alphanumeric Grouping:** We create a table where the **Signature** is the primary key, showing every `file:line` that produces that exact look.

**Example Signature Table:**
| Signature | Occurrences | Selectors |
| --- | --- | --- |
| `background:var(--accent-primary);color:#fff;padding:0.75rem 1.5rem;` | 5 | `.logout-button`, `.import-button`, `.send-button`... |
| `border:1px solid var(--border-subtle);border-radius:8px;` | 12 | `.card`, `.upload-box`, `.status-item`... |

### Phase 2: Value Bucketing & Token Normalization
We will reduce the entropy of raw values by "bucketing" them into the nearest approved tokens from `src/styles/tokens.css`.

| Attribute | Current Entropy | Target Buckets (Scale) |
| --- | --- | --- |
| Spacing | ~35 unique | 6 tokens (--space-xs to --space-2xl) |
| Typography | ~25 unique | 6 tokens (--font-size-xs to --font-size-2xl) |
| Radius | ~10 unique | 6 tokens (--radius-xs to --radius-2xl) |
| Colors | ~140 unique | ~12 tokens (Primary, Secondary, Success, etc.) |

### Phase 3: Structural Consolidation
Once values are normalized, we will identify:
1. **Shared Primitives:** Groups of selectors that share a substantial signature (e.g., buttons, cards, status-messages). These will be extracted into shared classes (e.g., `.btn`, `.card`).
2. **Component-Local Elements:** Unique signatures that remain component-specific. These will be renamed using BEM (e.g., `.main-dashboard__header`).
3. **Inline Styles Extraction:** Any `style={{...}}` blocks in JSX will be extracted into these signatures and moved to CSS.

## Implementation Order

### Phase 0: Setup & Audit
1. **Tooling:** Create `scripts/theme-tools/` and the `css-consolidator.mjs` script.
2. **Initial Audit:** Generate the first **Signature Inventory** to establish the baseline.

### Phase 1: Inline Styles Cleanup (Highest Priority)
Before sweeping CSS files, we must extract all `style={{...}}` blocks from JSX.
- **Static Blocks:** Move to CSS with semantic class names.
- **Dynamic Blocks:** Convert to CSS Custom Properties (e.g., `--dynamic-color`) to maintain theme safety.
- **Identical Clusters:** Identify repeated inline styles (e.g., hint text) and consolidate into a single shared class.

### Phase 2: Archetype-Family Attribute Sweeps
We group the E1-E7 files into "Families" with high reuse potential:
- **Wallet Ops:** E1 (Dashboard), E2 (Export), E3 (Auth), E4 (Locker).
- **QMail Panes:** E5 (AccountPane).
- **Global/Chrome:** E6 (App.css).
- **Onboarding:** E7 (ServiceSelection).

**Sweep Order:**
1. **Colors & Effects:** Map all raw hex/rgba to tokens.
2. **Typography:** Map all font-sizes to the project scale.
3. **Spacing:** Map all paddings/margins/gaps to tokens using 5% fuzzy matching.

### Phase 3: Structural BEM Migration
Perform the final selector rename and JSX `className` update per family, leveraging the **Signature Table** to identify where shared blocks (like `.btn`, `.card`) should replace duplicated code.
