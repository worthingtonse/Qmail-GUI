Track F — BEM class rename mapping
==================================

Required reading from the plan:
  §3.7  BEM rename rules            (lines 449–478)
  §13.4 semantic-landmark biases    (lines 1314–1338; affects which
        blocks should be promoted)

What to deliver:
  File: docs/theme.bem-mapping.md
  Contents: a complete mapping table of EVERY class currently used
  across the 22 CSS files listed in §12.4 (the E1–E22 file list), to
  its target BEM name.

  Suggested table format:

      Source file          Current class                    Target BEM class
      -------------------  -------------------------------  --------------------------------
      App.css              .update-modal                    .update-modal           (block, no change)
      App.css              .update-modal-header             .update-modal__header
      App.css              .update-modal-close              .update-modal__close
      App.css              .nav-tab                         .nav-tab                (block)
      App.css              .nav-tab.active                  .nav-tab--active        (modifier; combinator → modifier)
      ...
      MainDashboard.css    .glass-pane                      .glass-pane             (utility — keep)
      MainDashboard.css    .glass-sound-btn                 .glass-sound-btn        (utility variant — keep, document)
      MainDashboard.css    .account-confirm-overlay         .account-pane__confirm-overlay
      ...

  How to enumerate the classes:
    ripgrep on each file:
        rg '^\.[a-zA-Z0-9_-]+|,\s*\.[a-zA-Z0-9_-]+' --only-matching --no-filename <file>.css

    Then dedupe per file. You should expect roughly 30–80 unique class
    names per file (heaviest in MainDashboard.css ~250).

  Rules to apply (from §3.7):
    1. Block name = component name (e.g. .account-pane, .compose-modal,
       .nav-tab). Pick the smallest one already in use.
    2. Element = .block__element (single underscore replaced with double).
    3. Modifier = .block--modifier OR .block__element--modifier.
       Convert ".block.modifier-class" combinator selectors to .block--modifier.
    4. Utility classes (.glass-pane, .btn, .surface) — keep as-is; mark
       them in the "Utility / keep" column.
    5. Same-name collisions across files — namespace by file's component
       (.compose-modal__row vs .reading-pane__row). The block prefix
       prevents the collision.
    6. Don't rename classes that JSX uses dynamically (className={`foo-${variant}`}).
       Flag these in a separate "Dynamic className — manual review" section.

  Then a "Cross-file collision report" section: classes that appear in
  multiple CSS files with the SAME name but different styling. These
  need explicit block prefixes.

  And a "Heading-tag implications" note: if a renamed class is currently
  applied to a <div class="some-title"> that should be a heading per
  §13.3, flag it for the E-track agent to handle. You're not making the
  JSX change — just noting it so the agent doesn't miss it.
