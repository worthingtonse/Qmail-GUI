Out-of-Scope Observations
-------------------------
Recorded in docs\cla.bugs.txt:

  BUG-41 (LOW, UX polish) — Refresh chain double-notifies on
    loadEmails failure. loadEmails emits its own "Failed to load
    emails" error toast (pre-existing) AND handleRefresh emits the
    aggregate "Refresh completed with some service errors." Other
    refresh steps don't have this issue. Suggested fix: silent
    opt-in arg on loadEmails OR skip-aggregate-when-helper-toasts
    logic in handleRefresh.

  BUG-42 (LOW, code hygiene) — pingQMail alias has zero callers in
    src\. Per project conventions ("Avoid backwards-compatibility
    hacks…") it should be removed unless an out-of-tree consumer
    exists. Implementer kept it intentionally per the summary, so
    logging here for revisit.

  BUG-43 (LOW, UX double-notification edge case) — Client-side
    validation throw inside handleSend's try block ("Please provide
    at least one valid recipient address." at line 761) routes
    through markSendFailed → onSendFailure → dashboard error toast.
    Modal is still open and the validation error already shows in
    the modal's red banner, so the dashboard toast is pure noise.
    Edge case but real. Suggested fix: move the parseEmailList
    check into the pre-isSending validation block, OR teach
    markSendFailed to skip onSendFailure for client-side failures.
