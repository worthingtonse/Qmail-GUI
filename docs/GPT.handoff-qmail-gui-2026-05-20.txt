Important current findings
--------------------------
1. Critical likely mismatch: GUI send endpoint is stale.

   GUI:

       src\api\qmailApiServices.js
       sendEmail() calls:
       POST /api/qmail/net/messages/send

   Current rest_core registration:

       D:\Code\src\C\rest_core\api_src\api_handlers.c
       /api/qmail/net/messages/upload
       /api/qmail/net/messages/tell
       /api/qmail/net/messages/upload_and_tell
       /api/qmail/net/messages/download

   api_handlers.h explicitly says the legacy api_handle_qmail_send and old
   combined upload handler were removed. Use api_handle_qmail_upload and
   api_handle_qmail_upload_and_tell.

   First likely GUI fix:

       sendEmail() should call:
       POST /api/qmail/net/messages/upload_and_tell

   It should keep using application/x-www-form-urlencoded unless handler
   testing proves otherwise. Required body source is one of:
       body
       plain_text_qmail_path
       email_file

   Recipients are query/form params named to, cc, bcc. Attachments are passed
   as repeated attachment_file_path params, or legacy attachments.

2. Duration parameter mismatch in sendEmail().

   GUI sets:

       storage_weeks

   upload_and_tell handler reads:

       duration

   The handler defaults duration to 4 weeks if absent. If GUI wants user
   storage duration to matter, map storage_weeks to duration.

3. Task polling needs careful verification.

   upload_and_tell returns an async task_id and file_guid. Polling should use:

       GET /api/system/tasks?task_id=<task_id>

   Existing GUI code has had bugs where it expected result.data.status while
   getTaskStatus normalized to state/progress fields. Re-check ComposeModal
   after any send endpoint change.
