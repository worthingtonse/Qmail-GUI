5. REST_CORE ENDPOINT INVENTORY (the audit reference)
==============================================================================
The authoritative source of WHICH endpoints exist is:
  D:\Code\src\C\rest_core\api_src\api_handlers.c
function api_register_endpoints(). Every line of the form
  http_server_register_endpoint(server, "/api/.../...", handler, NULL);
is a real endpoint. Anything the GUI calls that is NOT registered there
is a hallucination by the GUI.

For QMail specifically, the handlers live in:
  D:\Code\src\C\rest_core\api_src\api_handlers_qmail_*.c
These files are organized by sub-topic (messages, inbox, folders,
contacts, drafts, attachments, tells, payments, identity, misc). The
breakdown is in D:\Code\src\C\rest_core\CLAUDE.md "File Organization"
table — read that first if a handler isn't where you expect.

Quick reference for the most-used QMail endpoints I touched recently:
  /api/qmail/local/identity/whoami
  /api/qmail/local/status
  /api/qmail/local/locker-pool/status
  /api/qmail/local/address/from-sn?sn=<n>
  /api/qmail/net/messages/upload_and_tell (POST or GET-with-query)
  /api/qmail/net/messages/download
  /api/qmail/net/beacon/peek?since=<ts>
  /api/qmail/db/messages/list?folder=0&limit=N
  /api/qmail/db/attachments/list?email_id=<hex>
  /api/qmail/receipts?guid=<guid>
  /api/system/tasks?task_id=<id>
  /api/raida/echo                    (this is now also called automatically
                                      every 5 min after bug #8 fix)

Each handler in api_handlers_qmail_*.c is the single source of truth for
which params it requires and what JSON shape it returns. Don't trust
docs/ in rest_core for this — read the handler.
