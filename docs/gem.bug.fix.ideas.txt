# BUG-51: Self-Contained QMail.exe & Core Management
Model: Gemini 1.5 Pro (CLI)
Date: 2026-05-24

## Current Analysis
The current `electron.cjs` attempts to find `core.exe` in `process.resourcesPath + '/backend/core.exe'`. In Electron's portable mode, `electron-builder` unpacks these resources to a temporary directory in `%TEMP%`. 

**The Problem:** 
1. `core.exe` is running from a temp folder, but the user expects it (and its data) to be visible/manageable relative to the `QMail.exe` location.
2. If `core.exe` is only inside the `.asar` or temp resources, the user can't easily see it or its `Client_Data` unless they know where to look.
3. Arguments like specific ports, debug modes, or the "Raida 11 fix" are not currently passed through from the `QMail.exe` launch command.

## Proposed Goals & Strategy

### 1. "Extract on First Run" (Self-Healing)
Instead of just running from the temp resources, `QMail.exe` should check if `core.exe` exists in the same directory as the portable launcher (the "Host Directory").
- **If missing:** Extract it from the internal resources to the Host Directory.
- **If present:** Run the one in the Host Directory (allowing for manual updates/replacements).

### 2. Unified Argument Passing
`QMail.exe` should capture its own command-line arguments and pass relevant ones to `core.exe`.
- **Arguments to support:**
    - `--port=N` or `-p N`: Use a specific port instead of a random one.
    - `--debug`: Pass `-debug` to `core.exe`.
    - `--raida11`: Pass whatever specific flag or environment variable is needed for the "Raida 11 fix".
    - `--clean`: Force re-extraction of `core.exe`.

### 3. Data Structure Management
`core.exe` handles `Client_Data` creation, but Electron must ensure the `cwd` (Current Working Directory) is set correctly to the Host Directory so that `Client_Data` appears next to the portable `.exe`.

## Implementation Plan

### Step A: Identify the Host Directory
Use `process.env.PORTABLE_EXECUTABLE_DIR` (set by electron-builder) or fallback to `path.dirname(process.execPath)`.

### Step B: The "Extraction" Logic
In `electron.cjs`, before `startBackend`:
```javascript
const hostDir = process.env.PORTABLE_EXECUTABLE_DIR || path.dirname(process.execPath);
const hostCorePath = path.join(hostDir, 'core.exe');
const bundledCorePath = path.join(process.resourcesPath, 'backend', 'core.exe');

if (!fs.existsSync(hostCorePath) || process.argv.includes('--clean')) {
  log('Extracting bundled core.exe to ' + hostCorePath);
  fs.copyFileSync(bundledCorePath, hostCorePath);
}
```

### Step C: Enhanced Argument Parsing
Capture `process.argv` and translate them into a flags array for `spawn`.
```javascript
function getBackendArgs(port) {
  const args = ['-port', String(port)];
  if (process.argv.includes('--debug')) args.push('-debug');
  if (process.argv.includes('--raida11')) args.push('-raida11'); // Example flag
  // Add other mappings as needed
  return args;
}
```

### Step D: Verification Build
1. Update `electron.cjs` with the extraction and argument logic.
2. Ensure `electron-builder.config.cjs` continues to include `backend/core.exe` in `extraResources`.
3. Run `npm run build-portable`.
4. Test by running `QMail.exe` and verifying `core.exe` and `Client_Data` appear in the same folder.
