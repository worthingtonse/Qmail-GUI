BUG-73 - Add Funds success needs See Receipt link
- Files: `src/api/qmailApiServices.js`, `src/qmail/screens/WalletActionModal.jsx`, `src/qmail/screens/WalletActionModal.css`
- After successful Add Funds from Locker, Folder, or Files, the success panel shows `See Receipt` when a receipt filename can be derived.
- Clicking `See Receipt` calls `/api/wallets/receipts?wallet_path=<Default>&filename=<receipt>` and renders the returned JSON inline.
- Added `getDefaultWalletReceipt()` in `qmailApiServices.js` instead of reusing `apiService.js` because QMail must honor the dynamic `backendPort` query used by Electron/random-port startup.
- Deposit and locker helpers now preserve the resolved Default wallet path in their returned data.
- Receipt filename derivation checks `receipt_id`, `receipt_path`, `task_id`, embedded receipt objects, and fallback task id. Core writes JSON receipts as `<Default Wallet>/Receipts/<task_id>.json`.

Important implementation notes:
- QMail wallet operations should target the Default wallet for spendable funds.
- Mail wallet remains for identity/mailbox key operations only.
- `WalletActionModal.jsx` has helper functions near the top for receipt filename derivation and formatting.
- For file/folder deposits, `/api/transactions/deposit` starts a task; the GUI polls with `waitForTaskCompletion()` and then derives the receipt filename from task data or the original task id.
- For locker downloads, `/api/locker/download` returns `task_id` and may include embedded receipt data; the GUI can derive `<task_id>.json`.
- Existing older receipt helpers in `src/api/apiService.js` use a static Vite port and should not be used by QMail renderer flows unless they are updated to match the dynamic port resolver.
