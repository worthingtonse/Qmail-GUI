Batch 10 Summary - FIX-22 + FIX-31
==================================

Scope
-----
Implemented Phase 2 Batch 10:
- FIX-22: Compose send-gating UX.
- FIX-31: Remove Parity Server Configuration.

Changes
-------
FIX-22:
- ComposeModal now initializes canSend to null and resets it to null while
  the RAIDA availability check is running.
- The Send button is disabled during the check and reads
  "Checking network...".
- Network readiness now depends only on getServers() and requires at least
  6 reachable RAIDA servers.
- When the check reports fewer than 6 reachable servers, Compose shows a
  warning with Retry and leaves a "Send anyway" override available. The
  backend remains the final authority on whether sending succeeds.
- Network-check failures are treated as the same warning path instead of a
  blocking red form error.

FIX-31:
- Removed getParityServer() from qmailApiServices.js.
- Removed getParityServer imports and calls from ComposeModal and
  AccountPane.
- Removed AccountPane parity state, loading state, refresh handler, and the
  Parity Server Configuration section.
